# Rule vs OpenAI(gpt-4o-mini) vs Hybrid 벤치마크 (2026-08-21)

- 대상: 할랄 인증서 100건 (`D:\halal_baseline_review_100`), 6필드(인증기관/인증국가/인증번호/유효기간/제조사/제조국)
- 산출물: `run_benchmark.py` (OpenAI 호출·리포트 생성), `halal_llm_benchmark_dashboard_org_alias_fixed_v2.html` (판정 대시보드)

## 결과

| 방식 | 필드 정확도(600필드) | 완전일치 문서 |
|---|---|---|
| Rule (기존 판독기) | 83.0% | 39/100 |
| Hybrid (LOW conf만 LLM 대체) | 69.8% | 13/100 |
| Full LLM (gpt-4o-mini) | 61.5% | 2/100 |

필드별 정확도(Rule / LLM / Hybrid):
- 인증기관 100.0 / 32.0 / 47.0
- 인증국가 92.0 / 73.0 / 78.0
- 인증번호 69.0 / 56.0 / 62.0
- 유효기간 78.0 / 80.0 / 78.0
- 제조사 78.0 / 62.0 / 77.0
- 제조국 81.0 / 66.0 / 77.0

## 인사이트

1. **인증기관 판별은 Rule이 압도적으로 우위** (100% vs 32%). LLM은 별칭을 정규화하지 않고 원문 그대로 반환
   (예: BPJPH → "Majelis Ulama Indonesia"). `organizations.py`의 기관 별칭 테이블이 실질적 가치를 만들고 있음.
2. **Hybrid(LOW conf만 LLM 대체)가 Rule 단독보다 오히려 낮음** (69.8% < 83.0%). LLM이 대부분 필드에서 Rule보다
   약하기 때문에, "confidence 낮을 때 LLM으로 보완"이라는 전제가 이 실험에서는 성립하지 않음.
3. 유일하게 LLM이 Rule을 앞선 필드는 **유효기간**(80.0% vs 78.0%) — 근소한 차이라 유의미하다고 보기 어려움.
4. 결론: 현재 세팅(gpt-4o-mini, 이미지 1페이지, 프롬프트 그대로)으로는 LLM을 신뢰 보완재로 쓰기 어렵고,
   Rule 결과를 우선하고 LLM은 참고값 정도로 두는 편이 낫다. LLM을 쓰려면 기관명 등 사전 정의된 값에 대해
   같은 별칭 정규화를 거치게 하는 후처리가 선행되어야 함.

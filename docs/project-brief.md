# 할랄 인증 관리 자동화 프로젝트 개요

세우(농심 그룹사)가 인도네시아로 수출하는 완제품의 원재료 할랄 인증서를 관리하는 사내 웹 시스템을 만든다.
원재료 약 310종의 인증서를 담당자 한 명이 엑셀로 수기 관리하던 업무를 자동 파이프라인으로 바꾸되,
판정이 확실한 건만 시스템이 처리하고 애매한 건은 사람에게 넘긴다.

## 배경

인도네시아는 유통 식품에 할랄 인증을 요구한다. 완제품이 인증을 받으려면 거기 들어가는 원재료
하나하나에 유효한 할랄 인증서가 붙어 있어야 한다. 원재료는 약 310종이고 인증서는 발급기관도
만료일도 제각각이다.

발급기관은 대부분 해외 기관이다. 말레이시아 JAKIM, 싱가포르 MUIS, 태국 CICOT 같은 곳에서 발급한다.
인도네시아 할랄 인증청 BPJPH는 이 해외 기관 중 일부만 인정한다. 인정 목록(LHLN)에 없는 기관의
인증서는 원재료에 쓸 수 없다. 그래서 인증서를 확보했다는 것만으로는 부족하다. BPJPH가 인정하는
기관이 발급했고 아직 만료되지 않은 인증서여야 한다.

### 지금까지의 업무 방식

담당자가 PMF(Products and Materials File, 원재료 마스터 엑셀)를 열어 다음을 반복했다.

1. 만료가 임박한 원재료를 눈으로 찾는다
2. 해당 원재료의 공급업체에 갱신 요청 메일을 손으로 쓴다
3. 회신을 기다렸다가 첨부된 인증서 PDF를 연다
4. 인증기관, 인증번호, 유효기간을 읽어 PMF에 옮겨 적는다
5. 공유폴더 규칙에 맞게 파일명을 바꿔 저장한다

월 5시간쯤 걸리는 루프였다. 정작 문제는 걸리는 시간이 아니라 이 방식이 실패하는 양상이었다.

만료를 하나 놓치면 그 원재료가 들어간 완제품 전체의 수출이 막힌다. 눈으로 찾는 방식에는 놓친 걸
뒤늦게라도 잡아낼 장치가 없다. 인증번호를 옮겨 적다 한 글자 틀리거나 날짜 형식을 잘못 읽으면 그게
그대로 마스터 데이터가 되고 나중에 할랄 심사에서 판단 근거를 요구받을 때 내놓을 기록은 담당자
메일함과 기억에 흩어져 있다. 기관별 인증서 양식이나 어느 기관이 교차인정되는지도 문서화되지 않은
암묵지여서 담당자가 바뀌면 처음부터 다시 쌓아야 한다.

## 목표

수기 루프를 자동 파이프라인으로 대체한다. 흐름은 이렇다.

```
만료 임박 원재료 선별
  → 업체별 갱신 요청 메일 생성·발송
  → 회신 첨부 자동 저장
  → 인증서 판독(OCR)으로 발급기관·인증번호·유효기간 추출
  → BPJPH 인정기관 목록과 대조해 교차인정 판정
  → 담당자가 예외 건만 검토·확정
  → PMF 갱신 및 이력 기록
```

다만 자동화가 처리하는 구간은 판단이 명확한 데까지다. 담당자는 판단이 갈리는 지점에만 붙는다.

| 목표 | 뜻 |
|---|---|
| 만료를 놓치지 않는다 | 만료 임박 원재료를 시스템이 선별한다. 사람이 찾아다니지 않는다 |
| 옮겨 적기를 없앤다 | 인증서 PDF에서 기관·인증번호·유효기간을 판독해 PMF에 반영한다 |
| 교차인정을 규칙으로 고정한다 | BPJPH 인정기관 목록 대조를 암묵지에서 코드로 옮긴다 |
| 근거를 남긴다 | 발송·판독·확정 이력을 쌓아 할랄 심사 근거자료로 재사용한다 |
| 예외만 사람이 본다 | 안전 조건을 통과한 건만 자동 확정하고 나머지는 사람 검토로 돌린다 |

### 하지 않는 것

인증서 진위는 판정하지 않는다. 위조 여부는 시스템이 다루지 않는다.

완제품 할랄 인증 신청 업무는 범위 밖이다. 원재료 인증서 관리까지가 대상이다.

머신러닝 모델로 판정하지 않는다. 교차인정과 필드 추출은 전부 규칙 기반이다. 판정 근거를 설명할 수
있어야 하고 할랄 심사에 그대로 제출할 수 있어야 하기 때문이다. 실험 목적의 학습 코드가 저장소에
있긴 하지만 운영 흐름에는 연결하지 않았다.

PMF를 대체하지 않는다. PMF 엑셀이 계속 단일 진실 원천으로 남는다. 시스템은 그걸 읽고 쓰는 도구다.

## 범위

포함하는 것은 만료 선별부터 갱신 요청 메일 발송, 회신 첨부 수신과 저장, 인증서 판독, 교차인정 판정,
담당자 검토와 확정, PMF 갱신 및 이력 기록까지다.

제외하는 것은 완제품 할랄 인증 신청, 공급업체 관리(구매·계약), 재고 및 생산 시스템 연동,
BPJPH 포털 직접 연동이다.

## 예상 산출물

| 산출물 | 형태 | 쓰는 사람 |
|---|---|---|
| 사내 웹앱 | 브라우저 화면. 만료 현황, 메일 발송, 판독 검토, 확정 | 할랄 인증 담당자 |
| 갱신된 PMF | 인증번호·유효기간이 자동 반영된 원재료 마스터 엑셀 | 담당자와 후속 업무 전반 |
| 정리된 인증서 파일 | 공유폴더 규칙에 맞춰 이름과 위치가 정해진 원본 PDF | 담당자, 심사 대응 |
| 이력 기록 | 언제 무엇을 보냈고 어떻게 읽었고 왜 그렇게 판정했는지 | 할랄 심사 대응 |
| 교차인정 규칙셋 | 기관별 판독 규칙과 BPJPH 인정기관 대조 로직 | 시스템 내부, 인수인계 |
| 운영·설계 문서 | 설치, 데이터 흐름, 규칙 유지보수 절차 | 후임자, 유지보수 담당 |

## 성공 기준

두 가지는 타협하지 않는다. 유효기간이 지난 원재료가 선별에서 빠지는 일이 없어야 하고 자동으로
확정된 건 중에 잘못된 데이터가 들어가는 일이 없어야 한다. 둘 다 0건이 기준이다.

나머지는 지향점이다. 담당자가 직접 눈으로 검토하는 건수가 전체 회신 대비 유의미하게 줄어들고
할랄 심사에서 판정 근거를 시스템 기록만으로 제출할 수 있으면 된다.

앞의 두 기준과 자동화율은 맞바꾸지 않는다. 자동으로 처리되는 비율이 낮아지는 건 감수하고 앞의 둘을
지킨다. 구체적인 수치 목표는 운영 합의 후 확정한다.

## 제약과 리스크

| 항목 | 내용 |
|---|---|
| 운영 환경 | PMF와 서류가 Windows 공유폴더에 있다. 다른 운영체제에서는 PMF 연동이 동작하지 않는다 |
| PMF 파일 형식 | 매크로가 든 엑셀 파일이다. 잘못 저장하면 매크로가 날아간다 |
| 판독 품질 | 스캔 상태와 기관별 양식에 따라 판독이 흔들린다. 규칙으로 보정하지만 한계가 있다 |
| 규칙 유지보수 | 기관이 인증서 양식을 바꾸거나 BPJPH 인정 목록이 갱신되면 규칙도 따라 고쳐야 한다 |
| 초기 검토량 | 자동 확정 조건을 의도적으로 보수적으로 잡았다. 초기에는 사람이 볼 건수가 많을 수 있다 |

## 안전 원칙

이 업무는 실패 비용이 비대칭이다. 잘못 자동화한 1건이 수동 작업 100건보다 비싸다. 그래서 자동 확정
로직은 다음을 항상 지킨다.

- PMF에 이미 있는 인증번호와 유효기간을 새 판독 결과로 덮어쓰지 않는다
- 판독한 발급기관이 메일 발신 기관과 다르면 자동 확정을 막고 사람 검토로 넘긴다
- 제품명과 제조사는 인증서 원문에서 확인될 때만 PMF 표준명으로 정규화한다
- BPJPH가 발급한 인증서의 판독 유효기간은 비워둔다
- PMF에 있는 유효기간보다 과거인 날짜가 판독되면 자동 확정을 막는다

확실하지 않으면 비워두거나 사람에게 넘긴다. 이 원칙이 자동화율보다 우선한다.
